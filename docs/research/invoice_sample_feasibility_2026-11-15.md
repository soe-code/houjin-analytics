# インボイス公表データによる分析サンプルの実現性調査

調査日：2026-11-15（日本時間）。対象は適格請求書発行事業者の公表データ。

法人番号サンプルと同様に、全事業者にダミー売上を付けた5分割Parquetを作成できる。
最初の対象には東京都の法人分を推奨する。実CSVを取得し、最新情報の抽出・既存データとの
結合・ダミー値生成・均等5分割の件数をDuckDBのメモリ内で確認した。
今回行ったのは調査と集計であり、インボイス版Parquetの出力や既存パイプラインの変更は行っていない。

## 公開データの仕様

- 国税庁は全件データをCSV・XML・JSONで提供する。法人、人格のない社団等、個人は別ファイル。
- 法人分は全国を5地域グループに分割している。分割番号002は東京都のみ。
- 法人番号を持つ事業者の登録番号は「T＋法人番号」。法人番号との完全一致結合が可能。
- CSVはヘッダなし24列。登録番号、事業者処理区分、人格区分、最新履歴、登録・更新・取消・失効日、
  法人名、所在地、地域コードなどを含む。売上・請求金額・取引明細の列はない。
- 全件ファイルにも履歴行が入る。「1行＝1事業者」のサンプルには最新履歴 `latest = '1'` を利用する。
- 個人事業者分の一括ファイルでは、氏名・屋号・所在地など10項目の値が削除されている。
  登録番号・登録日等の集計は可能だが、実在の名称・住所による分析サンプルには向かない。
- 人格区分 `kind = '2'` は人格のない社団等も含む。法人番号との結合可否は人格区分だけで判定せず、
  法人用ファイル `h_all_*` と社団等用 `j_all_*` の出所を区別する。

出典：[公表情報ダウンロード](https://www.invoice-kohyo.nta.go.jp/download/)、
[リソース定義書1.5版](https://www.invoice-kohyo.nta.go.jp/files/k-resource-dl.pdf)、
[登録番号の構成](https://www.invoice-kohyo.nta.go.jp/about-toroku/)、
[個人分の提供項目変更](https://www.invoice-kohyo.nta.go.jp/news/r04/r04news04.html)。

国税庁の[全件ダウンロード画面](https://www.invoice-kohyo.nta.go.jp/download/zenken)から
東京都法人分 `h_all_20261030_csv_002.zip` を取得した。
画面の更新日表示は2026-10-30。解凍後は `h_all_20261030_002.csv`。
ファイル名の日付は作成日であり、分析基準日や月末日と同一とは仮定しない。

|---|---:|

| CSVサイズ | 106,227,319 bytes |
| CSV列数 | 24 |
| 履歴を含む行数 | 588,896 |
| 登録番号の種類数 | 565,153 |

| 最新履歴内の登録番号重複 | 0 |
| 最新履歴内の法人名・所在地の欠損 | 0 |
| 既存の法人Parquetとの結合成功 | 562,699（99.5658%） |
| 法人Parquetと未結合 | 2,454 |
| 結合後に実売上 `revenue_jpy` がある事業者 | 909 |
| ダミー売上を生成できた事業者 | 565,153（100%） |

比較先は `data/processed/houjin_enriched_part*.parquet` の全5ファイル、計1,362,626法人。
結合条件は `invoice.registrated_number = 'T' || houjin.corporate_number`。
法人番号データの入力基準日は2026-07-31で、インボイス側のファイル作成日と一致しない。
未結合2,454件の原因は未調査。時点差・所在地変更などが候補だが、原因として確定していない。

最新履歴を持つ565,153事業者には、失効・取消や将来登録も含む。
「現在有効な登録事業者数」としてこの件数を使わない。

## 作成案

インボイスの最新行を基準にし、法人データをLEFT JOINする。
未結合の2,454件もインボイス側の名称・所在地を使って保持する。
ダミー値は結合先に依存させず、法人用登録番号の数字部分から直接生成する。

| 列 | 内容 |
|---|---|
| `invoice_registration_number` | T付きの登録番号。公式項目名 `registratedNumber` から変換 |
| `corporate_number` | 法人用登録番号のTを除いた13桁。社団等・個人にこの変換を適用しない |
| `invoice_name`, `invoice_address` | インボイス側の名称・所在地 |
| `prefecture_code`, `city_code` | 元の都道府県2桁・市区町村3桁を文字列で保持 |
| `registration_date`, `update_date`, `disposal_date`, `expire_date` | 日付型に変換 |
| `invoice_process`, `invoice_latest` | 元の区分を保持 |
| `revenue_dummy_jpy` | 全件に生成するダミー売上。実売上とは別列 |
| `revenue_jpy` と財務の出典列 | 法人Parquetと結合できる範囲で保持 |
| `has_houjin_match` | 法人Parquetとの結合有無 |
| `source_file`, `source_file_created_date`, `analysis_as_of_date` | 出所・作成日・分析基準日を区別して記録 |

ダミー売上の生成式は既存サンプルと合わせる。同一法人なら両サンプルで同じ値になる。

```sql
CAST(
    (md5_number_lower(substring(registrated_number, 2)) % 10000 + 1) * 1000000
    AS BIGINT
) AS revenue_dummy_jpy
```

実CSVの最新565,153行で、全件に100万円〜100億円の値が付くことを確認した。
これは表示・集計の動作確認用であり、事業規模や実際の売上を推定する値ではない。

出力案は `invoice_enriched_part01.parquet` 〜 `invoice_enriched_part05.parquet`。
登録番号順に `ntile(5)` で分けた場合、行数は113,031・113,031・113,031・113,030・113,030。
Parquetの実ファイルサイズは未測定。既存の5分割出力処理は `houjin_enriched` テーブル名に
依存しているため、インボイス用テーブルに対応させる小さな変更が必要。

法人番号データ側の1,362,626行を基準に登録情報を付ける別案も可能。
今回の異なる時点のファイル同士では562,699件（41.2952%）が結合したが、
未結合行をすべて「未登録」と断定することはできない。

## 登録状態・履歴分析の扱い

- `latest = '1'` は最新履歴であり、登録有効フラグではない。
- 最新行に2026-10-30より将来の登録日が430件、将来の失効日が684件あった。
  `process = '03'` だけで直ちに「分析基準日時点で失効済み」とするのも不適切。
- 最新行の登録日が基準日以前で、取消日・失効日が未設定または基準日より後、という条件で
  2026-10-30時点をスクリーニングすると542,308件。ただし最新行による日時条件の集計であり、
  過去の全登録期間を復元した結果ではない。
- 過去時点の有効性分析には登録・失効・取消・再登録のイベントを整理する必要がある。
  古い「新規」行には終了日が入っていないケースを確認したため、全履歴行を未終了の期間として
  OR条件でまとめると、失効・取消済み事業者を有効と誤判定する。
- 名称・所在地の変更については最新情報のみが配布されるため、現在取得した全件ファイルだけで
  過去時点の名称・所在地の完全な履歴を復元することはできない。
- 当月の最新状態まで更新したい場合は月次全件に日次差分を反映する。今回は日次差分は未取得。

仕様上の根拠：
[リソース定義書](https://www.invoice-kohyo.nta.go.jp/files/k-resource-dl.pdf)、
[全件・差分の説明](https://www.invoice-kohyo.nta.go.jp/download/)、
[再登録を含む公式サンプルの説明](https://www.invoice-kohyo.nta.go.jp/download/index.files/k-sample-explain-r0310.pdf)。

## 実装時に必要な作業と利用できる分析

必要な作業は、法人CSVの取得・24列のロード・最新行の抽出・法人データとのLEFT JOIN・
ダミー列の付与・5分割出力。取得時に公開画面からファイル管理番号を解決する必要があり、
今回観測した管理番号を固定値として実装しない。

地域別の登録事業者数、登録時期別の件数、登録状態の区分、ダミー売上帯別の集計、
法人番号サンプルとの照合・可視化に利用できる。
請求書そのものの取引明細や実際の請求金額・消費税額・入金状況を分析するには、別の取引データが必要。

既存の `jp-invoice-entity-resolution` にはインボイス用のテーブル定義があるが、調査開始時点で
実データはなく、DuckDB内も法人番号ステージングテーブルのみ。取得CLIは法人番号用だけが実装されていた。
調査では一時領域 `/tmp/houjin-invoice-research/` に公式CSVと集計結果を保存し、
既存の法人Parquet・DuckDBおよび他プロジェクトは変更していない。
